## 用户行为

- 默认关闭。梁相案牍保留 2×2 主工具格；整格点击“日终上香”切换已开启/已关闭，保存期间显示“保存中”。23:59、默认方向及运行条件只放在悬停/键盘聚焦提示内，不占常驻空间。
- 右键夯或拉只保存默认方向，在原反馈行显示“日终默认夯/拉”；键盘菜单键或
  Shift+F10 同样可设置。设置方向不投票、不自动开启开关。
- 核对香火仍有修复作用：丢弃未确认的本地观察后重新读服务端账本。保留它的
  确认流程，收进“显示异常？”折叠入口；日常观察、声明、刷新与重连继续自动执行。
- DSH 必须运行并加载该 Profile；浏览器可以关闭。关闭 DSH、睡眠、断网或额度
  不足时不保证完成，午夜后不补投昨天的余额。

## 最小执行模型

不物化逐炷 TTL 队列，不做日内自动投票、策略方向、提前十分钟多轮排期或新限流。
每个模式、每个业务日仅形成一笔普通倾炉意图；有余额才形成。23:59 起，重新读取
权威余额，申请 `min(remaining, VOTE_COUNT_MAX)`，服务端按现有预算决定实际接受量。
当前单次最多申请 500 炷；实际可用预算可能更少，因此只承诺按限额尽量上香。
成功后当天不再自动投第二笔，新到账香火不会触发逐炷追投。

Host 使用一个可取消的定时器。日间只等待目标时刻，不增加后台 HTTP 轮询。
在线时以 bootstrap/snapshot 的 `server_time` 校正 Host 时间，按后端下发的
`business_timezone` 找到下一业务日边界，支持 DST 的 23/25 小时日；不相信浏览器
日期。无需变更 Backend wire，最终投票资格仍由后端决定。离线才使用显式本地时区。

手动与自动共享 Host 串行入口。长按开始时发送一个仅限 Host 的短暂操作标记，给尚未发出的手动请求留位；
取消/断开的标记最多 5 秒自然失效，不是投票或余额。已有手动请求先结束，随后
至少留 2 秒安静窗口；排队任务开始执行、异步读账和意图落盘后都重新检查，慢请求不会跳过等待。
自动在实际发出前再读账。自动准备过程中出现新的手动请求会先让位；已发送的
请求保持自己的归属，后续手动请求等待其权威结果。Backend 的事务扣香、余额、
限流、幂等和旧案拒绝保持最终权威，多标签页不能各自花一份余额。

每笔自动意图的业务日、梁案、方向、count、request ID 先写入 Host 持久化，再发出。
结果不确定、重启、偏好改变后的重试均保留原始 payload 和 ID，不生成新意图逃避
幂等。失败最多每 5 秒重试，结束前 5 秒不再启动新请求；已发送请求若跨日到达，
由 Backend 拒绝旧案。新日不重放旧意图。在线/离线分别保存最近一笔回执，空间有界。
模式切换中的请求暂停，排队请求不得改投另一模式。存储尚未就绪时不可开启。

设置与回执放在现有 Host `settings` 表的独立 `day_end` 行，沿用公开的
`storageDomain` 接口，不改 DSH core。校验仍接受旧配置；该行保留旧版设置校验
需要的 `authorityPreference` 字段，不改变实际模式行。新增 wire 偏好为可选字段，
旧 Host 不提供时新客户端将该开关标为不可用；浏览器不保存权威设置或自动任务。

## Issue #4

原 Host 在启动时固定本地 interval，忽略 bootstrap 的 `snapshot_refresh_seconds`，
后端调慢发布无法减少请求。现在 Host 订阅当前服务，仅当有效 cadence 改变时重建
唯一计时器；离线或没有可用 wire 的启动阶段使用本地 env；在线连接帧以默认 1 秒重连，
bootstrap 成功后采用后端值，切换模式与重新 bootstrap 后跟随新的权威值。
普通状态更新不重置等待，卸载移除订阅与计时器，值限制在既有 1–3600 秒范围内。

客户端继续使用 SSE；其 wire cadence 控制悬停刷新最短间隔（至少 2 秒），避免
悬停绕开后端减负。显式打开面板仍能立即刷新。保留 additive wire 契约，旧客户端
和旧 Host 的滚动升级路径不因删除字段而中断。
