# 连接与消息开销

## 1.3.0-alpha.6 通信候选

本轮不改变 wire 格式、行情 cadence、记账事务或安装身份的信任级别：

- 新建云订阅只发送本人的首帧，公共读集合在一秒内复用，不重新遍历所有旧连接。
- 正常广播每次最多处理64个连接，再让出事件循环；同一时刻最多一轮广播，避免积压。
- 公共市场、当前点和分钟烛线每轮读取一次。钱包仍按本人查询；仓位只在同一安装身份、同场且钱包版本不变时复用。缓存只在服务进程内，绝不作为扣款权威。
- 市场固定SQL使用最多128项的预编译缓存，不以身份、请求ID或历史长度扩张。
- 累计香火/累计香客仅为公共展示，每秒至多扫描一次；换案、清理和复位立即失效，不缓存私人余额或扣款资格。
- 复用最多2048个已解析的公钥对象，逐请求签名、时效和设备校验不变；同一请求复用刚读到的身份行，访问记录仍逐请求写入。精确相同时间戳的业务日期转换复用结果，不近似跨日边界。
- 普通请求只做一次完整签名校验。未知身份仍先验签后拒绝准入，不能借普通请求自动注册；已有身份仍检查设备绑定并更新访问记录。
- 慢连接的首次背压等待 `drain`，期间合并为最新状态；缓冲超过64KiB或持续阻塞25秒则断开。重连首帧、心跳、身份撤销与卸载清理保留。
- Host重连采用有上限的随机指数退避；只有收到有效帧并稳定30秒后才重置退避。取消旧流不等待可能卡住的网络清理承诺。
- 默认监听队列2048；后端HTTP空闲65秒、代理60秒，减少重复建连与复用已关闭连接。现有请求头截止时间保留。
- Caddy保留 `ProtectProc=invisible` 与 `ProtectKernelTunables=true`，但使用 `ProcSubset=all`，让Go读取内核 `somaxconn`；`pid` 会隐藏该路径，导致Go回退到128。安装此配置后需在维护窗口重启代理，再以实际监听队列核对；普通reload不会保证重建已有监听socket。下述容量与结算测试期间仍保留原代理配置；后续部署记录见本节末尾。

接口上香/仓位响应继续立即返回，公共状态仍每秒合并；历史与回执保持有界冷通道。不新增轮询、不引入新服务或数据库。

## 1.3 累计钱包候选

当前独立候选已增加 Linux Backend → 本机 Host 的认证 SSE。本机 Host 主动建立连接，服务器沿同一 HTTPS 响应流推送公共快照、阶段和本人的钱包变化；浏览器继续使用原有本机 SSE。

- 每 Host 只有一条云流，公共快照每秒最多生成一次后分发；相同内容不重复发送。
- 公共市场版本持久化，公共批次/池量共享缓存；稳定订阅不逐连接开启写事务。
- 私人钱包只推给本人。需要核对用量水位时补读个人账本，不从余额变化猜测声明到账。
- 声明响应不确定时先核对原累计水位，保留请求提交时的本地观察边界，避免重复凝香或吞掉在途新用量。
- 云流健康时低频校准；旧后台不支持或连接失效时，保留原 cadence 回退与有界重连。
- 25 秒心跳、连接数/缓冲上限和卸载清理均保留；历史 K 线与回执走分页冷通道。

候选的具体契约与验证见 [`MARKET_WALLET.md`](MARKET_WALLET.md)、[`MARKET_VALIDATION.md`](MARKET_VALIDATION.md)。以下是已发布 1.2 系列的轮询与本机 SSE 基线，不能用它推断候选仍每秒轮询。

## 本轮改进

Host 保持原有权威刷新节奏，只省去内容完全相同的 SSE 状态帧。
比较完整 wire 的全部字段，仅排除过程内递增的 `revision`；没有删减字段或改用差量协议。
每次新连接仍发送完整状态，25 秒心跳保留。

真实 HTTP/SSE 双标签页回归中，首次连接后连续触发 60 次内容相同的权威读取通知：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 每标签页完整状态帧 | 61 | 1 |
| 两标签页合计完整状态帧 | 122 | 2 |
| 权威读取通知 | 60 | 60 |
| 心跳、初次连接、重连完整状态 | 保留 | 保留 |

这是固定输入下的帧数回归，不代表线上流量的固定降幅。真正变化的每一帧仍立即发送：
香火余额与凝香进度、同版梁位、统计、广播发布和失效、日终偏好、档案游标、刷新节奏、
在线可用性、模式及 Host epoch。重连接受新 epoch 的低 revision，旧帧拦截规则不变。

## 保留的连接行为

- 每个 Host 一条权威快照计时器，采用后端 cadence；标签页数量不会增加该定时器。
  默认 1 秒一次快照，每 5 个 tick 补读个人账本，避免其他 Host 的余额变化长期不可见。
  默认稳定期约为每分钟 60 次快照和 12 次个人读取，启动、操作与失败重试另计。
- 每标签页初次读取状态与独立档案冷通道，再用一条 SSE 接收状态；没有浏览器后台轮询。
  档案后续仅按 `archive_version` 拉取增量，不塞进日常状态帧。
- 悬停刷新受 `max(2 秒, 后端 cadence)` 限制；显式打开立即刷新。
  并发 bootstrap、snapshot、history 已合并在各自现有入口，避免重复在途读取。
- Token 声明合并 1 秒内的连续结算，内容未增长时不提交；投票先冲刷尚未提交的声明。
  倾炉与日终上香复用一笔 `count` 意图，不按香火数量循环发请求。
- 日终关闭时没有排期请求；开启后日间只有 Host 定时器，浏览器可关闭。
  手动长按保护只在日终已开启时通知 Host，保留这一步以避免自动上香抢先。
- 断线保留最后状态与在线偏好，使用有界重连退避；不靠公共快照解除身份故障。
  卸载清理 SSE、心跳、计时器、订阅与可取消请求。

## 未采用的优化

不延长默认轮询、不停掉隐藏标签页状态、不删除个人账本补读，也不缓存或节流显式打开。
这些做法会改变投票反馈、广播失效、跨端余额或恢复时效。
不引入跨标签主从选举、SharedWorker 或服务器长连接改造；当前收益不足以抵消生命周期、
DSH 兼容和故障接管成本。服务器请求数量本轮不变。

## alpha11 第一批：等价工作共享（未发布）

以 alpha10 功能提交为对照，不改变云端每秒推送、心跳、校准与故障恢复节奏。

- Host 同一云帧中的快照、钱包／市场及当前烛线全部应用后同步通知一次；独立云帧仍逐帧交付，无计时合并窗口。
- 同一 Host 的各浏览器页共享一次订阅与各频道的编码结果；每页仍收到完整状态，初次／重连发送当前全量。
- 烛线与回执仅合并身份、查询参数、状态版本及写入代次相同的在途读取。请求完成即删除；不加 TTL、不沿用写入前的在途结果。alpha11.1补充位置请求退出屏障，响应不确定时，之后的新查询也不会沿用写入期间的旧在途结果。
- 首屏显式市场 GET 保持权威读取；随后本机订阅可接续健康云流的完整投影，断线／无云帧时重新权威读取。
- Backend 每次广播只编码一次公共快照、烛线、市场字段；钱包与持仓按安装分别编码。仅同帧工厂产生的对象可使用公共模板，其余退回普通完整序列化。
- 广播每片最多64订阅或4毫秒工作后立即让出执行权；不降低频率，不丢弃订阅或事件。按安装连接计数直接维护，仍执行原2000总连接／每安装3条上限。

本批不更改协议、账本 schema、财务公式、交易限额或分钟桶。容量复测沿用两来源签名 HTTP＋云端 SSE 方法；该压力发生器直接访问 Backend，Host 去重与本机转发另由真实安装、集成及专项链路验证，不能把 Backend 容量试验说成400个完整DSH桌面的浏览器性能。

## 双来源通信优化复测（2026-11-08）

第一批优化已实现，消息完整性与独立账本核对通过；香港持续网络验收未通过。短时低中档负载有改善，但不能据此把现有备机认证为稳定400并发。以下结论更新本文件前次“400作为阶段容量”的建议：当前网络故障未排除，短时成功与持续稳定必须分开判断。

### 实现与发现的功能问题

| 问题 | 用户影响 | 本批处理及验证 |
| --- | --- | --- |
| 同一云帧按字段分别通知 | 页面可能先看到新快照与旧钱包／烛线混在一起 | 完整帧同步应用后通知一次；独立后续帧逐帧立即送达，未引入计时合并窗口 |
| 同安装多页重复冷读 | 同一查询重复验签、访问数据库及传输 | 仅共享身份、查询、状态版本与写入代次均相同的在途查询；完成立即移除，无TTL缓存 |
| 交易响应不确定后复用旧在途读 | 新查询可能接到写入期间启动的旧结果 | 进入写入及退出时都推进读取代次，失败也执行；旧版故障注入可复现，新回归通过 |
| 每标签页重复订阅与编码 | 页面增加会重复本机序列化工作 | 每Host一次订阅，各频道一份完整编码，分别交付全部标签页；首帧／重连全量保留 |
| 广播重复编码公共内容及连接扫描 | 随连接数增长占用事件循环 | 每帧公共JSON一次、私人字段按所有者隔离；连接计数直接维护；每片最多64订阅或4ms后让出执行权 |

首屏显式市场GET仍为新鲜权威读取；随后本机订阅接续健康云流，无有效云流时重新读取。模板编码仅用于受控同帧对象，其他情况退回完整JSON；等价性及跨所有者隔离有回归。未改协议字段、精度、schema14、财务公式、限额、签名校验、逐笔回执、每秒公共推送、心跳、校准或断线恢复节拍。相同信息的重复工作被共享，有效信息没有删减。

### 香港持续验收未通过

首轮持续测试在17:02 UTC前后发生HTTPS与SSH同时停顿；当时后端约37%单核、事件循环P95约37ms，本地原服务健康接口仍约2ms。多次重试（含拆分异地发生器、逐档预热）仍出现大量超时。优化后预热100用户也出现约2秒P95和错误，在进入完整时间计划前停止，避免继续占用共享入口。不能把提前中止的300／400档空记录写成零错误通过。

拆分发生器的400尝试，本机3001请求／708失败、异地3442／648失败；它与短时曲线启动方式不同，不作为可比性能提升数据，也不足以完全排除发生器影响，但持续故障没有因拆分进程消失。后续预热中止前组16,013请求／2348失败，后组3940／132失败；负载长度和停止点不同，不做百分比提升比较。

31.2秒受控抓包共20,000个TCP头、971条流，观察4914个出站相同序号／长度的重复发送，HTTPS重复间隔可达6–15.7秒，SSH流也出现约14.7秒重复；内核观测到cwnd=1、退避7、重传超时约79秒。重复段不是精确丢包率；抓包零窗口统计包含复位报文，不能据此认定接收窗口是根因。现有证据定位到跨端口TCP确认／重传异常，未确认具体云端、线路或端点根因；未擅改MTU、拥塞算法、卸载或路由。

云控制台8项网络检查通过；这不等于两地端到端无故障。停压后各来源5次严格TLS健康访问恢复，仍不能说明持续负载问题消失。已提交云服务商网络排查工单；仅请求诊断，不授权重启、改网或付费升级。

### 原始资源曲线补核与200并发规划

后续从归档的每秒资源采样补绘CPU、内存、请求速率和网卡曲线，没有启动新一轮压测。

该速率包含重试、不包含SSE消息；不是最大QPS试验，400档还包含集中重连。

整机100%表示两个vCPU全部忙碌；进程占核按单核100%换算，不能混用分母。
可用内存使用内核MemAvailable（包含可回收缓存），不把多个进程RSS相加当成整机实际占用。
采样窗口没有显示内存耗尽趋势；整机高CPU含既有演练、代理和系统开销，不等于测试后端独占两个核。
同时，长测在低后端CPU时仍发生跨端口TCP停顿，CPU竞争不能解释所有网络故障。
