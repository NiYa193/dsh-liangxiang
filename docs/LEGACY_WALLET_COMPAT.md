# 钱包升级与旧版兼容

范围：未发布的1.3候选与正式1.2协议。兼容层不设置自动失效日期；发布仍需独立批准。线上维护版没有因这些源码修改自动升级。

## 兼容矩阵

| 客户端 → 后端 | 可继续使用 | 边界 |
| --- | --- | --- |
| 旧1.2 → 新钱包后端 | 凝香、夯／拉、梁祠、原身份与当日赠香 | 继续显示并消费真实当日额度；跨日结余及收益留在唯一服务器钱包，升级后可见。旧版没有交易入口 |
| 新候选 → 旧1.2后端 | 凝香、夯／拉、梁祠；404的云SSE自动回退原刷新方式 | 旧服仍按日账规则；市场接口未开放，不能承诺累计资产或交易 |
| 同一身份已使用新钱包，再混用旧二进制 | 日账仍能如实表示时可用 | 当日实际已用大于当日生成，或冻结后可用低于旧版日剩余时，旧个人接口返回HTTP412 `wallet_upgrade_required`；资金与身份不清空 |

旧二进制无法显示“可用／冻结／累计”三种概念，也无法诚实表示“今天生成10炷但消费了昨天的20炷”。旧界面收到412后可能只显示网络错误并重连，**不能承诺其会显示新的中文升级说明**。这只限制已混用新功能且日账无法表示的身份；没有使用新钱包功能的旧用户不会仅因后端升级或跨日结余而被整体阻断。

未发布的alpha8市场客户端只识别v1/v2，不认识新v3交易日程；参与v3新场需安装alpha9。
alpha9仍读取已保存的v1/v2场次及回执，不改其冻结资金或时点。这一候选市场兼容边界
不等于强制正式1.2用户升级：1.2没有市场，基础接口仍按上表过渡。

## 单一账本与能力协商

新Host在HTTP及SSE请求发送 `x-liangxiang-wallet: cumulative-v1`，与梁子称呼的展示策略头独立。没有该值或值未知的个人HTTP响应，按真实日账投影：

```text
claimed = 实际当日已入账Token
earned = floor(claimed / token_per_incense)
used = 实际当日接受的上香数量
remaining = earned - used
remainder = claimed % token_per_incense
```

不伪造Token、不裁掉实际用香、不把交易收益写成凝香。旧请求还在投票事务内受上述日剩余额度约束，实际扣款仍来自同一服务器钱包；新旧不能各花一次，也不能花被冻结的资金。旧界面暂不显示的跨日结余不会销毁。

能力头只是协议选择，**不是认证、权限或防伪凭证**。签名仍验证安装身份、方法、路径、正文和时效。市场写接口本来就要求签名和服务器钱包可用性；是否带能力头都不会授权操作别人的钱或绕过冻结。不得把客户端自行声明支持钱包理解为获得额外额度。

旧版无法表示一个已冻结账户时，Token声明可能已按真实单调水位入账，而响应被412限制。重试相同声明不再生香；不能因为旧界面报错就回滚、重复计入或重置身份。解除冻结、真实日账重新可表示后，旧接口可恢复。
