## 现行行为

| 社区夯票占比 | 称呼 |
|---|---|
| 零票 | 待开梁，梁位 `--` |
| 有票且 <25% | 小难梁 |
| 25%–<50% | 梁工 |
| 50%–<70% | 梁总 |
| 70%–<85% | 梁神 |
| 85%–<95% | 梁圣 |
| ≥95% | 梁祖 |

判定、图像和范围提示使用同一快照及规则版本；梁位保留六位小数并截断，
不会因四舍五入提前跨档。入口、主面板、梁祠、读屏文字和升降音效均支持小难梁。
个人香火只驱动香火环，不驱动社区称呼；投票仍只有夯、拉两种。

## 升级与历史兼容

- 当前规则为 `liangzi-v0.2-25-50-70-85-95`；旧规则
  `liangzi-v0.1-50-70-85-95` 保留低于 50% 为梁工的含义。
- 已有梁案保留开案规则；下一个业务日或显式新开梁案使用新规则。重启不改变当前案。
- 封存日档采用当天最后一案的规则；周/月采用最新覆盖日的规则。先汇总原始夯拉票数，
  再计算比例和称呼，不平均各日比例或等级，不回写旧档案。
- 在线和离线均读取新旧规则；旧离线记录缺少规则版本时按旧规则解释。
- 新 Host 通过 `x-liangxiang-liangzi-policy` 声明新规则能力；旧客户端收到兼容展示。
  转换只改变响应副本中的称呼、边界和规则标识，票数、序列、余额和幂等票据不变。
  新旧客户端重放同一投票仍只扣一次。
- 未知封存规则被明确拒绝，避免静默改写历史；实时投票保留既有快照恢复机制。

## 图像与验证

小难梁沿用同一成人梁子角色：眼镜、灰粉卫衣、小蝴蝶结和收手姿势。生产图为
256px 透明无损 WebP；图像测试逐像素核对全部七态的可见 RGBA，透明边缘不会变底色。
构建保留 DSH 模块工厂格式，客户端继续受 raw 700 KB / gzip 400 KB 预算约束。

主要回归：

- `tests/domain-liangzi.spec.ts`：零票、25% 精确边界、全部档位与六位小数截断。
- `tests/liangzi-policy-upgrade.spec.ts`：新旧客户端、重放、日切及混合规则封存历史。
- `tests/domain-archive.spec.ts`：原始票数加权、临时周期与规则版本。
- `tests/liangzi-art.spec.ts`：透明度、尺寸与可见像素一致性。
- `tests/browser/liangzi-policy.spec.ts`：真实安装后投拉，入口与面板同步显示小难梁。

上述边界和兼容回归已有通过记录；最终候选的完整验证、安装包与浏览器结果统一见
[当前架构与验收矩阵](CURRENT_ARCHITECTURE.md)。源码合入不代表正式发布或生产部署。
