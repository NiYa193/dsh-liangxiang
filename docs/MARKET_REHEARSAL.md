# 香港备服隔离演练

本流程验证未发布交易候选，不是公开发布。目标地址、SSH身份和端口只从本机忽略的配置或进程环境读取，不写入仓库。生产节点、备服原实例及原数据库不参与模拟交易。

## 固定隔离边界

| 资源 | 专用值 |
| --- | --- |
| 服务 | `liangxiang-backend-rehearsal` |
| 源码与版本收据 | `/opt/liangxiang-rehearsal`、其下 `VERSION` |
| 配置 | `/etc/liangxiang-rehearsal.env` |
| 数据库 | `/var/lib/liangxiang/rehearsal/liangxiang-rehearsal.sqlite` |
| 业务时钟 | 同目录 `clock.json` |
| 监听 | `127.0.0.1:4195`，不增加公网入口 |

只通过 `LIANGXIANG_DEPLOY_MODE=rehearsal bash scripts/deploy.sh` 部署，并以同模式运行 `scripts/deploy-check.sh`。只接受显式 standby 目标、预期主机名及干净的已提交源码；沿用原代理配置指纹检查。原实例、代理、SSH、系统时钟和防火墙均不修改。若同机维护或压测正在独占目标，等待其明确释放后才能部署。

## 业务时间与签名

独立入口 `lib/rehearsal-backend.js` 复用真实服务、HTTP和SQLite事务；普通 `lib/backend.js` 不加载演练模块。启动需要 `LIANGXIANG_REHEARSAL=1`，固定回环监听、专用数据库和时钟文件，并强制拒绝未签名请求。演练入口、独立 `lib/rehearsal-runner.js`、脚本和原始美术PNG不在npm文件白名单内。

时钟文件格式为 `{ "epoch_ms": 1794153600000, "anchor_wall_ms": 0, "rate": 0 }`：业务时刻为起点加真实经过时间乘倍率；`rate:0` 暂停，便于检查封盘与午夜两侧。首次部署写入起点，已有数据库或时钟绝不重置。控制文件只由运维/演练进程原子替换，没有HTTP改时接口。运行中拒绝时间倒退，重启沿用控制文件；不可将旧控制文件回灌已运行的数据库。

请求签名时效、改仓限流和网络超时仍用真实时钟。投票桶保留每分钟500炷规则，恢复时间与数据库投票时间同用演练业务时钟；此演练不验证真实时间下的额度压力。模拟Token资金由各身份签名申报；这仍是软信任合成数据，不证明真实DSH用量。

私有演练入口可用 `LIANGXIANG_REHEARSAL_TICK_MS` 调整实际采样间隔，未配置时默认200ms，只接受20–1000ms整数。720倍（真实两分钟一个业务日）建议40ms：每次约推进28.8个业务秒，正常调度下覆盖每分钟的当前真实聚合。此选项只由演练入口读取，不改变普通后台、签名时效或交易规则；专用部署模板明确设置40ms，并由部署检查校验固定配置。

采样只记录执行时刻，不插值、不回填缺失分钟、不制造上香或交易；若调度或网络落后，保留真实缺口。缩短间隔会提高单机数据库检查频率，最短20ms对应最高每秒50次，不能视为容量结论。720倍下原200ms间隔每次已跨2.4业务分钟，看到缺口属于演练采样分辨率，不能据此推断真实时钟下也缺失数据。K线的变化来自真实签名夯／拉上香，做多／做空只是冻结仓位，不直接改变梁位或成交量。

2026-11-08本机空载微基准：Node22.19、720倍、每档6秒、无客户端／上香／仓位。200ms实记29桶（覆盖区间缺40个分钟桶），40ms和20ms各实记72桶且区间内无缺桶；单核CPU分别约0.77%、2.02%、2.66%。40ms和20ms的SQLite/WAL/SHM合计分配约1.32MB，200ms约0.79MB；这是运行中已分配文件大小，不是每日增长率。40ms已达到同样的分钟覆盖，毋须默认升到50Hz。该短时本机结果不证明香港多客户端性能，远程负载仍需另验。

## 手动与自动通路

- 手动：真实独立DSH Profile安装当前tarball，经 `scripts/rehearsal-relay.mjs` 的回环监听和SSH标准输入/输出访问专用后台。它只允许连接远端固定回环4195，不开启SSH转发权限或公网代理。原本地演示Profile保留。
- 自动：在专用实例旁以服务账号运行独立 `lib/rehearsal-runner.js`（源码为 `scripts/rehearse-market.ts`），以至少12个独立签名安装身份走真实HTTP；密钥与续跑状态只放专用私有目录，报告只输出编号和汇总。
- 分阶段：prepare后可重启专用服务，finish再推进后两盘与午夜，verify核对已完成结果。只运行all不得宣称验证了进程重启。

报告分别记录部署收据、手动操作、自动负向场景、真实参考点与整炷派彩、冻结/可用守恒、重启/重试、SQLite完整性及原实例前后健康。未执行或仅在本地覆盖的项目须单独说明；小规模演练不能推导千用户容量。

## 连续背景活动

`lib/rehearsal-activity.js` 复用上一轮12个安装身份及真实钱包；私有轮次目录、上一轮
`state.json` 和上述专用 `clock.json` 必须显式传入。不能指向日常 Profile、普通后台或远程URL。

```bash
node lib/rehearsal-activity.js --mode prepare --state-dir "$ROUND_DIR" --prior-state "$PRIOR_STATE" --clock-file "$CLOCK_FILE" --max-days 10
node lib/rehearsal-activity.js --mode run --state-dir "$ROUND_DIR" --prior-state "$PRIOR_STATE" --clock-file "$CLOCK_FILE" --max-days 10
```

先在暂停时钟下prepare，再由操作员只向前恢复演练时钟；run不自动加速。最多运行10个
业务日，达到上限或收到停止信号时暂停该演练时钟。新轮不得覆盖旧轮，续跑不得改变既有上限。
目录权限0700、私有状态0600，并自动写入忽略规则；密钥、状态、原始日志和目标配置永不提交。

每天仅两向各1炷开场，随后12个模拟身份错峰、小笔1–3炷、平缓偏向与随机回撤；
全局请求间隔至少90ms，每钱包留600炷用于交易。真实签名HTTP仍负责扣款及限流，
未知请求落盘并沿用原ID重试。交易窗口完全读取服务端时点，保留投入、改仓、撤回与重入。
本轮不增加Token声明或自动补足余额；资金不足即停止相关上香，普通日赠香保持原规则。

行情仅来自这些实际接受的夯拉和演练采样，不补假K线。5秒脱敏 `live.json` 显示编号、
钱包、仓位、已结算收益、背景用香及包含手动参与者的全池守恒；没有安装ID、密钥或入场票。
`state.json`、`background.json` 必须保留，分别保存身份/交易意图与唯一待确认上香意图。
此运行验证交互、时序与账本，不是容量测试；提高采样或活动频率后仍需实测资源和错误率。
构建后运行 `node scripts/ci/check-rehearsal-entry.mjs`，确认真实独立监听、健康检查、
停止及活动参数拒绝均正常；它只使用本机专用临时数据库，不访问远程环境。
